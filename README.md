# Подбор автозапчастей

Клиентское приложение на React + Redux для API поиска автозапчастей: двухэтапный подбор номенклатуры.

1. **Поиск производителей.** Вводим артикул → запрос `?number=...` → список брендов, выпускающих деталь с этим артикулом.
2. **Предложения и аналоги.** Выбираем бренд → запрос `?number=...&brand=...&analogues=on` → таблица: название и производитель, артикул, склад, цена, остаток. Аналоги помечены отдельно.

## Стек

React 18, Redux Toolkit + react-redux, Bootstrap 5, Vite. Без TypeScript.

## Запуск

```bash
npm install
cp .env.example .env    # и впишите ключ покупателя в VITE_PARTS_API_KEY
npm run dev
```

Без ключа приложение запускается в **демо-режиме** на данных в формате API: попробуйте артикулы `7160500039S` и `OC90`.

## Как устроено

```
src/
  api/partsApi.js       запрос к API, разбор ответа и ошибок
  api/mock.js          демо-данные для запуска без ключа
  store/searchSlice.js состояние двух этапов: thunk-и fetchBrands и fetchOffers
  components/          SearchForm, BrandList, OffersTable, Loader, ErrorAlert
```

- **Состояния.** У каждого этапа свой статус `idle / loading / succeeded / failed`: лоадер, ошибка с кнопкой «Повторить», сообщение «ничего не найдено».
- **Ошибки.** Обрабатываются сбой сети, HTTP-ошибка, некорректный JSON, поле `error` из ответа API (например, «Invalid key client!») и пустой ответ (API возвращает массив с одним пустым элементом).
- **Гонки запросов.** Если пользователь начал новый поиск, ответ на устаревший запрос игнорируется (сверка `requestId`).
- **Цена и остаток.** По документации поле `price` у товара использовать нельзя, поэтому цена и остаток берутся из `warehouses`; одна строка таблицы — товар на конкретном складе.
- **CORS.** API работает по http и без CORS-заголовков, поэтому в dev-режиме запросы идут через прокси Vite (`/api` → сервер API).
- **Поиск запускается по Enter или кнопке**, а не на каждое нажатие клавиши, чтобы не тратить квоту запросов API.
